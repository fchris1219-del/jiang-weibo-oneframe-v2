# 酱微博 · 单轮廓档位版

这是不覆盖旧版的全新仓库。微博的发帖、评论、私信、推荐流与个人主页功能沿用原实现；本版重做的是启动壳、设置、存档、API 与上下文注入。

## 安装

1. 下载 `酒馆助手脚本_酱微博.json`。
2. 在酒馆助手中导入并启用。
3. 进入任意角色聊天，点击“博”悬浮按钮。按钮可自由拖动，位置会保存在本机。

移动端启动壳会跟随 `visualViewport` 的真实可视高度，并为顶部/底部安全区留边，兼容 TT 酒馆顶部栏、横竖屏与软键盘造成的视口变化。

## 存储分层

- 全局设置：写入 SillyTavern `extension_settings.jiang_weibo_oneframe_v2`，跟随酒馆服务器配置。
- 角色／聊天档位：档位定义、档位配置与档位记录全部写入当前聊天的 `chatMetadata.jiang_weibo_oneframe_v2`。层级为“角色 → 聊天 → 档位”，切换角色或聊天不会看到别处创建的档位。
- 档位记录：写入 `chatMetadata.jiang_weibo_oneframe_v2.slotRecords[档位ID]`，切换下拉选项会立即热切换，不需要再点“切入”。
- 档位初始化：`wb_lore` 只写入当前档位；可手动从首楼读取并覆盖，不再向正文楼层回写。
- 微博、评论、私信不写入正文楼层；`localStorage` 只作旧数据兼容和离线镜像。

## API 与上下文

- 默认使用酒馆当前主 API，通过 `generateRaw` 发送微博专用消息数组。
- 选择独立副 API 后才改走副通道；Token 保存后不回显，并会自动拉取模型列表。
- 每个档位可选最近聊天（默认 3 条）、手动总结或不注入前文。
- 世界书支持按“世界书名称”整本扫描，以及按多个“条目名称”扫描；扫描词可用中文逗号、英文逗号或换行分隔，并可拆成独立词条标签。整本扫描只选择原本未禁用的条目，列表也支持整本勾选/取消。
- 详细原生版/简约表达版可选；只能编辑表达与内容规则。协议标签、字段名称、分隔符和编号格式固定内嵌，模板不能覆盖；详细版默认内置饭圈/竞圈真实 ID 生成指导。
- “微博预设”将微博提示词、初始化 `wb_lore`、NPC 微博账号、拉取数量、角色/User Personality、聊天前文、世界书、信息隔离和自定义条目分组管理；除 Char 账号资料外，所有会随角色脚本导出的配置都在这里编辑。
- 微博预设顶部提供默认空白的“System 附加说明”；填写后会作为请求列表第一条 `system` 消息发送，并随模板导出。
- 角色卡、User Persona 与世界书在微博内只读，可单独决定是否注入；信息隔离规则始终注入。
- 「防止重复」固定注入当前聊天×当前档位的已有微博/评论/私信摘要，并锁定 user/char 微博 ID 为本档位设置值。
- 注入类预设条目可独立设置 depth（0 最靠近本次任务），并显示每条估算 Token；纯参数类的「拉取数量」不显示虚假的 depth/Token。内置「热梗注入」、高权重自定义 ID 池和可选「正文 NPC 私信」。
- 预设模板从系统默认复制，可保存多份；创建时可选“全局模板”或“角色模板”。全局模板对所有角色、聊天和档位可见；角色模板只对当前角色可见，但在该角色的不同聊天与档位中都可使用。模板能够携带提示词、普通/热梗世界书扫描规则、手动热梗内容、生成数量、NPC 与 ID 池；应用后的配置仍写入当前档位。
- 选择“系统默认预设”导出时，会得到最原始的 `酱微博.json`：不携带任何角色、NPC、ID 池或世界书选择。只有自建模板导出时，才会把模板、Char 微博账号资料、注册 NPC 账号、自定义 ID 池与世界书的“书名＋条目名”可移植绑定嵌入新启动器脚本；不会导出 User 微博账号资料，也不携带 API Token、聊天记录、世界书正文或内部 ID。
- 导出的 JSON 文件名与酒馆脚本内部名称统一为“预设模板名称＋微博”；模板名称已经以“微博”结尾时不会重复追加。
- 推荐微博、推荐热评、单帖评论、散落私信、私信续聊以及“全部拉取”的数量均可分别设置。
- NPC 微博账号作为独立预设条目，可绑定世界书、填写独立发帖要求并调整注入深度；应用后按当前聊天×当前档位隔离，也可在主页中切换角色/NPC 账号。
- 档位可新建、切换和删除；删除档位会同时删除当前聊天中的该档记录，并且至少保留一个档位。
- user 发博支持公开、仅自己可见、指定 char/NPC 分组可见；私信联系人可分享自己有权看到的已有信息流微博。
- “全部拉取”用一次模型请求同时返回推荐流、路人私信和角色微博。

设计参考了 [ST-BaiBai-Book](https://github.com/baibai-git/ST-BaiBai-Book) 的 `extension_settings`、`chatMetadata`、主 API 回退与上下文构建方式。


### 柏宝书原生模式：明确的选择与裁剪规则

1. 历史摘要：原样读取 `baibai_book_memory_history` 注入槽。由柏宝书决定被隐藏摘要节点、压缩层级及其原生相对时间；小微博不再自行计算截止楼层，也不调用 `getHistory({before})`。
2. 聊天全文：逐一遍历当前 `context.chat`。仅当 `is_system === true` 或楼层正文为空时排除原文；其余楼层完整保留原文、user/assistant 角色和原有顺序，包括可见的 `bbs_omit`。**不设置 N 楼、字符上限或自动截断百分比。**
3. 当前状态、时间标签：原样使用 `baibai_book_memory_state` 和 `baibai_book_time_tag`；历史置前，状态依据柏宝书 D1/D2 放在最新可见 AI 前后，时间提示接近最终微博任务。位置只影响顺序，不改变内容选择。
4. Token 处理：不自行估算后裁剪。日志给出准确的 UTF-16 字符数和请求 JSON UTF-8 字节数；预设 UI 的 Token 数为估算，仅展示。若超过模型上下文容量则保留原始接口错误，提醒用户调整上下文，绝不静默删楼。不能保证完全复制酒馆主聊天的 Token 自动裁剪。
5. 审计记录：生成分组预览里会列出保留的楼层编号、被隐藏的楼层编号、空正文楼层、摘要节点数、覆盖情况和块字符数。实际生成时原始日志 META 还记录确切请求总字符数及 UTF-8 字节数；同一请求只抓取一次原生上下文，防止预览快照与发送内容不一致。
6. 插件未就绪、缺少原生提示词槽、三个槽都为空时，明确报错且不执行小微博自制的聊天选取算法。
